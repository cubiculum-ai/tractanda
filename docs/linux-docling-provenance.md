# Linux Docling compiler-input provenance

The `tractanda.linux-docling-compiler-inputs.v3` descriptor provenance binds the actual native converter input boundary. The versioned selection is:

- `Packages/TractandaClient/Package.swift` and the entire `Packages/TractandaClient/Sources/TractandaClient` tree.
- `Packages/TractandaDocuments/Package.swift`, `Packages/TractandaDocuments/Package.resolved`, and the complete `Sources/DoclingRGB`, `Sources/DoclingRaster`, `Sources/TractandaDocumentConverter`, and `Sources/CDoclingRaster` trees.
- The complete `Packages/TractandaDocuments/RuntimePatches` and `Packages/TractandaDocuments/ThirdPartyNotices` trees, and `config/model-artifacts.json`.
- Exact executed/imported or closure-generation recipes: `scripts/build-linux-ml-component.py`, `scripts/produce-linux-payload.py`, `scripts/package-linux.py`, `scripts/package-macos.py`, `scripts/validate-docling-model.py`, `scripts/export-linux-ml-component.py`, `scripts/build-docling-linux-native.py`, `scripts/build-docling-native.py`, `scripts/linux-docling-provenance.py`, `scripts/generate-linux-docling-binding.py`, `scripts/assemble-linux-docling-component.py`, `scripts/prepare-kali-linux-component.py`.

Each selected path must exist as the expected regular file or real directory. Capture descendant files with relative path, size, mode and SHA-256, refuse links and special files, and retain bounded traversal. The two generated Swift files remain in these trees. Validate their finite templates and normalize only the four baseline and architecture digest slots to fixed placeholders. A missing Kali admission uses a nil slot until native qualification. Record actual final file hashes separately. Record the versioned selection rule and exclusions in provenance. The packaging registry and component manifests are bound separately as output indexes.

Caller audit: the actual standalone Swift build selects `Packages/TractandaDocuments`; that package depends on local `TractandaClient`, its own exact `Package.resolved` and pinned VMLX/crypto. `P.mirrored_pins` is invoked on that package, not the root package. The converter targets the four source trees above. `build-linux-ml-component` imports `produce-linux-payload`, which imports `package-linux`, which imports `package-macos` and the validator; the patch application imports the Linux patch helper from the selected RuntimePatches tree. Native raster source and recipe inputs, pinned external revisions, actual native ELF/provider closure, model assets, toolchain and CPU flags remain bound by the selected files plus independent descriptor evidence.

Deliberately outside this converter scope: `Tests` directories, fixture-only verifier scripts, `Packages/TractandaEmbeddings`, standalone raster check targets, root `Package.swift`, root `Package.resolved`, root `VERSION`, packaging registry and generated component manifests. They are not read by the standalone converter compiler invocation. The final product/source and package receipts still independently bind all shipped public files, registry and component manifests. `python3 scripts/test-linux-docling-provenance.py` checks sensitivity across each selected root, stability under unrelated test, verifier and embedding edits, finite digest-literal normalization and link rejection. These checks do not replace native ELF, model, or runtime admission.
