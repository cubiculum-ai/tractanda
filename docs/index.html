Tractanda

A shared knowledge base for people and AI agents. Keep information once, categorize it in several ways, and choose views that fit the task.

Get started on a Mac

Install the Apple Silicon preview package, then open the local web client. Sign in with your computer account’s username and password. A new package installation provides a sample database; you can change or delete its example items and categories.

The package includes the server, terminal client, MCP adapter and their runtime libraries. The bundled semantic-search edition includes the Qwen embedding model and its runtime. You do not need Xcode or Swift to use the downloaded package.

The installer sets up system LaunchDaemons for the server and bundled embedding service. They start at boot. Installing an update upgrades and restarts the managed services while preserving the database and its connection settings.

To use the terminal interface, open Terminal or iTerm and run:

tractanda-tui

The installer normally creates this command in /usr/local/bin. Its stable target is /Users/Shared/Library/Application Support/Tractanda/current/bin/tractanda-tui. If that command name was already occupied, use the full path.

Choose a database

Connection profiles select a database. Omit the option to use the configured default, or choose an existing profile:

tractanda-tui --profile NAME

NAME is your profile name; there is no special profile that must literally be called “default”. Multiple databases have separate stores and connection settings; for example, a main store named production and a separate test store. The web board’s Project selector chooses a project within the connected database.

The local TUI uses your existing OS identity through its Unix socket connection, so it does not ask for your password again. The browser uses its own sign-in session. For an empty installation, custom database names, ports, upgrades or uninstalling, see macOS installation.

One item, several dimensions

An item can hold a note, message, person, action, reference material or a view definition. Most simple entries use the generic Item type. Editing an item creates a new revision; its identity stays the same. Human-friendly reference labels may be shown alongside that identity.

Categories are ordinary items with selection properties. Membership can come from a rule, a manual inclusion or a manual exclusion. An item can belong to several categories without being copied. Parent categories also include matching members of their children, unless an applicable exclusion prevents membership.

The category system is multidimensional. For example:

ItemPossible categories
Call Fred about Saturday’s barbecueWho: Fred · What: Barbecue · Means: Phone
Review the roof inspection reportWhat: Building project · Work type: Review · Priority: High
Keep the receipt for a replacement partWhat: Building project · Knowledge role: Reference, if you create that category

These are examples, not required names or fields. The starter template supplies dimensions such as Who, What, When, Where, Means, Priority, Urgency and Status, with supporting categories. All of them are editable and deletable. “All items” is simply the empty filter: the implicit root, not another stored category.

Combining dimensions narrows the result. Phone + Fred can find calls involving Fred; adding a project category limits it to that project. Information need not be a task to belong in the knowledge base.

Classifications are memberships. Priority, urgency, assignment, work type, optionality and workflow status do not need parallel text or Boolean fields. Assign the relevant categories. Actual facts—dates, estimated duration, document text, phone numbers and relationships—remain item properties.

Deleting a category does not delete its member items. Access permissions are separate: belonging to a category does not grant anyone permission to read its items. Personal category decisions can differ from shared decisions.

Use the web Kanban board

The web client is one example of a Tractanda front-end. A project board selects items belonging to the chosen project and a status category. A project does not need a special task class or a separately saved Kanban view.

  1. Choose a project from Project. All projects combines the available project hierarchy. Refresh projects discovers newly added projects.
  2. Use Search tasks and the category filter to narrow the loaded board. Switching projects clears those local filters. The selection is recorded in the page URL, so you can bookmark it.
  3. Open a card to edit its title, description, working notes, checklist and displayed category assignments. Use Save to Tractanda to publish the edit, or Cancel to discard the draft.
  4. Use New task to create an ordinary item associated with the selected project and its configured default category.
  5. Drag a card between columns to change its status-category assignments. Other memberships remain intact. An item assigned to several displayed status categories can appear in several columns.

The card editor shows category choices from the view’s configured axes. Change priority or assignment by checking the appropriate categories. Unknown properties are preserved; an unrelated save does not add empty fields or a hidden card-order value. Clearing a nonempty description or working-notes field removes that field. API clients can still deliberately store empty text, which is distinct from a missing value.

An open draft or unresolved save blocks project switching. If the server rejects a stale edit because someone else changed the item, review the newer revision before applying your changes. If the result of a save is uncertain, use the retained retry operation; do not recreate the item to guess whether the first save worked.

A configured completion category checks the card’s checklist and dependencies before completion. The board’s labels, default category and completion category are data, not hardcoded status names.

Export HTML and Export JSON save snapshots. Editing an exported HTML file does not change the server. Keep it as a portable report or an independent snapshot, not as a synchronized database.

Define views and choose their order

A view combines category filters, optional text or metadata criteria, sorting and presentation. A temporary view can answer one question; save a useful definition to reuse it. Any ordinary item can carry a saved view definition.

In the TUI, select a saved view and use Edit view definition. The form keeps its criteria, sorting and column settings together. Choose which properties or category dimensions to display, their titles and widths, and any section categories. Save the complete definition as one edit.

Columns and cards have different ordering rules

  • Kanban columns / report sections: an explicit section list defines their order. An implicit project board uses that list as a preferred sequence, then adds other eligible status leaves. Otherwise the category hierarchy’s sibling order applies.
  • Items within a section: the view’s sort applies. Category sorting follows effective membership in the root’s immediate child categories, ordered by categoryOrder, then name and ID. Inherited membership counts. An item matching several branches takes the first-ranked branch; unranked items stay last in either direction.
  • No explicit sort: normal queries show most recently modified items first. The sample Project view supplies a Priority category sort. A project can override its Project root’s presentation and sort independently.

The browser preserves the server’s item order. It does not infer priority from a text field or assign sortOrder on every save. Existing views may explicitly sort by ordinary metadata such as sortOrder.

For an advanced category-backed column or sort target in the TUI form, enter category:<axis UUID>. Use an ordinary field name, such as subject or dueAt, for owned metadata. The API guide describes the stored definitions.

Work in the terminal

The TUI starts in the Views workspace. Its selector is beside the report, with an optional item preview below. The Categories workspace similarly combines category navigation with either member items or a category inspector. Focus determines which selection a command acts on.

Key or controlUse
F1Open context help.
F10Open the global menu. Use arrow keys and Return, or the mouse. Unavailable commands are dimmed.
F9 in a main workspaceSwitch between Views and Categories. In many editors and temporary panels, F9 cancels or closes instead.
Tab / Shift-TabMove focus or move between form fields. The active pane is visually distinguished.
F8 in a main workspaceSwitch selector/report focus. In an editor it may be Save; follow the bottom key labels.
F11 / F12Show or hide the preview / refresh the workspace, when enabled. The menus provide the same actions on terminals with fewer function keys.
Ctrl-N, Ctrl-E, Ctrl-SNew, edit and save where applicable. The focused selector may act on a view definition rather than a report item.
Ctrl-QQuit. Follow any prompt concerning an unresolved operation.

The bottom function-key strip is the guide for the current context; inactive functions are blank. Terminal applications may intercept Command keys, so Control equivalents are available for common commands. Some keyboards need Fn with the function keys.

Mouse support includes selections, menus, scrolling and category breadcrumbs. Click an ancestor breadcrumb to go back, or its child-menu control to choose a child category. Terminal resizing preserves the current working state. Drag the preview divider or use View menu commands to adjust the preview height.

In Categories, choose Items or Category for the right-hand pane. The Category menu provides those modes; Shift-F2 toggles them. Outline versus connected-tree presentation is available in Category preferences, and Ctrl-T toggles it in that workspace.

Use the Tractanda menu’s Settings / Appearance and Category preferences for colors, presets, active/passive panes, cursor appearance and layout options. Custom colors and cursor controls depend on what the terminal supports. Your terminal application controls its font and window size.

Teach a category

The category learner uses examples of membership and exclusion. Open Learning, choose a category, review its examples and settings, then train it. It may need more positive and negative examples before it can provide useful suggestions.

Accepting a suggestion creates an ordinary category assignment. Excluding an item records a negative decision; a suggestion alone does not change membership. Manual decisions retain authority. Reset discards the derived model for that category without deleting items or accepted assignments; train again when ready.

Learning is scoped to the material the caller may read. Suggestions are experimental, and automatic classification is not implemented. Category learning is distinct from semantic search: the former learns membership examples, while the latter retrieves text by similarity.

Search beyond the current board

The web board’s search box filters its loaded cards. Native/API text search uses SQLite FTS5 over subject, body and owned text metadata such as working notes and checklists. It omits blank values and operational metadata. It does not follow references or search attachment bytes.

If a result seems missing, an agent or API client can use extracted-text diagnostics to see what text is eligible for indexing and whether the FTS and semantic indexes are current. Source, FTS-input and summary projections serve different questions. This does not search attachments or prove that the item matches a particular query.

Metadata expressions use the supported portable Spotlight-style query language. For example:

subject ==[cd] "*chess*"
estimatedMinutes <= 20

Category paths combine category filters by intersection. Relative-date categories are reevaluated when queried using their configured time zone; their changing membership does not require rewriting the items.

Semantic retrieval is supplemental. When configured and indexed, it searches the same owned-text corpus using embeddings. Check its coverage before assuming every item is indexed. The model/index can be rebuilt independently of the original records. Attachment extraction and automatic reminders are not provided by this preview.

Share context with AI agents

The same items and categories are available to the CLI, TUI, browser and MCP clients under the caller’s permissions. Agents can construct temporary views for a task; they do not have to create a saved view for every query.

Install the repository’s shared skill and connect the MCP adapter using an existing connection profile. Start discovery with tractanda_info and tractanda_describe, then the served introduction and references. An agent should discover the actual categories and their IDs rather than assume that a starter taxonomy is present. Restarting the adapter may not refresh the harness’s tool list; reconnect or refresh discovery if a new tool is missing. Some harnesses require a fresh session. Available category queries and membership explanations remain useful while the catalog is stale.

Tell an agent which project and task it may work on. An agent launched under your OS account has that account’s access; a tool name does not create a separate identity. Separate agent accounts and managed provisioning remain future work. See skill installation and agent access.

Keep and recover your data

Canonical revisions are self-contained files. The managed macOS installation separates them from its rebuildable indexes:

ContentDefault location
Records and durable settings/Users/Shared/Library/Tractanda/Stores/NAME
Derived metadata, text and vector indexes/Users/Shared/Library/Application Support/Tractanda/Indexes/NAME

Back up the complete canonical store and its ownership/permissions, not just the SQLite index. If an index is lost, the server can rebuild it from canonical records. Normal access is through clients; direct file editing is an administrative repair operation.

Current permissions govern the item’s entire history. Revoking access also revokes access to old revisions through the server. To share current content without earlier history, make a separately shared copy. Categories never replace those permissions.

Only one server writer should manage a store. Copying the directory with a sync service does not provide supported multi-server synchronization. Uninstalling through the supplied setup tool preserves canonical data; review the installation guide before administrative changes.

Troubleshooting

The browser cannot connect.
Use the configured database’s address; the default is http://127.0.0.1:48728/. Check that its managed service is running. A working local TUI uses a Unix socket, so it does not by itself prove that the HTTP listener is available.
The board is empty.
Check the selected project, local search/category filters, status assignments and your access rights. Project knowledge without a status does not appear on its Kanban board.
A save needs a retry.
Keep the pending edit and retry it after reconnecting. Do not repeat it as a new create operation. After a prototype migration, review old pending requests before resubmitting them.
Keys act differently in a text field.
Text editing and navigation have different contexts. Check F1 and the bottom key strip, or use F10. Command keys may be consumed by the terminal; use the documented Control alternative.
What changed after an upgrade?
Check the server version in the web sidebar, reload the page, and reconnect long-running TUI/MCP clients when instructed. Replacing a binary does not replace the code already loaded by an existing client process.

Preview scope

The macOS preview has managed startup, signed/notarized packages, a web example, TUI and agent API. Linux source/runtime work continues, but a ready Linux installer is not part of this preview.

Attachments, synchronization/offline replicas, a native SwiftUI app, scheduled automations and broader feed integrations remain planned. Hierarchical saved-view organization is also future work. The HTTP service is local-loopback oriented; this is not a public Internet deployment guide.

Formats and APIs can change before 1.0. Keep backups and follow migration notes.
