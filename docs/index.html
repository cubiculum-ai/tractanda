A shared knowledge base for people and AI agents: versioned items, overlapping categories and reusable views.

Start a local store

swift build
TRACTANDA_BIN="$(swift build --show-bin-path)"
"$TRACTANDA_BIN/tractanda" init "$HOME/Documents/Tractanda/demo"
"$TRACTANDA_BIN/tractanda" serve "$HOME/Documents/Tractanda/demo" /tmp/tractanda-demo.sock

The Unix service works with the CLI, TUI and stdio MCP adapter. Use a separate evaluation store and keep backups: formats and APIs are experimental.

Items, categories and views

An item can be a note, message, person, action, category or view definition. An edit publishes a new immutable revision. Categories overlap: the same item can belong to several contexts without being copied. A saved view is a capability of an ordinary item, not a container.

Access is separate from categorization. Current item permissions govern current content and all history. One server writes a store; do not use independent writers against synchronized copies.

Shared daemon and browser example

One daemon can host the native Unix API, an optional loopback browser/API surface, and MCP HTTP:

"$TRACTANDA_BIN/tractanda" daemon STORE SOCKET --http-port 48728

STORE and SOCKET are positional arguments separated by a space. HTTP is loopback-only; --no-http leaves the native listener alone. Optional board presentation is either --view ID or --project-root ID --status-root ID [--project ID].

For repeated local use, service prepare|install NAME STORE --shared creates user-level launchd/systemd registration and copies needed bundled resources. The compatible legacy native service remains available without --shared. This does not install a dedicated system account or a system service.

People, browsers and AI agents

Unix clients are identified by their socket peer credentials. Browser/API users sign in for a bearer session; on macOS password verification uses OpenDirectory. Linux verification of another user's password requires a separate privileged PAM helper deployment, which is still pending installation and real-account testing. Do not run the daemon as root merely for PAM.

Native TractandaAuth/createSession with empty arguments makes only the connected peer's own token. HTTP cannot select a UID or mint a token with it. HTTP /mcp is Streamable HTTP JSON with bounded per-user sessions; it has no SSE or replay. Stdio MCP remains available.

A tool label is not an OS identity. Run an agent host under its intended account and grant only explicit item permissions. Full managed agent accounts and homes are deferred.

Literal and semantic search

Literal text search is a literal FTS5 phrase over subject, body, and owned tagged-text metadata such as working notes, checklists, labels and custom text. It does not follow references or extract bytes, attachments or remote content. Root-only operational fields, including migration receipts and template identifiers, are excluded; nested ordinary text remains included. Blank text values and their labels are omitted. Named metadata SQL predicates are separate.

Semantic retrieval is optional and uses the same owned-text corpus as literal search. Its input encoding is item-text-utf8-v2. Extraction-rule versions are part of the index profile: upgrades rebuild the disposable semantic index, preserving the selected model and canonical records. Before claiming coverage, inspect semantic status, especially inputEncoding, profile and coverage fields. LSM behavior is unchanged.

Recovery and identity

Canonical revisions are self-contained files; SQLite metadata, FTS and vector indexes are disposable derivatives. Back up the canonical items/ tree and required deployment permissions. UUIDv1 IDs intentionally reveal time/host-node provenance. Production must use a real host node; CI's synthetic node is only for disposable tests.

System administration can be configured through the canonical access configuration. It recognizes root and OS administrator membership (macOS admin, Linux sudo, or an explicit override) per request. Existing stores retain legacy service-owner administration until migrated.

Proof-of-concept limits

  • Loopback HTTP is not an internet-facing gateway.
  • Managed startup, Linux semantic verification and privileged PAM-helper installation/testing remain pending.
  • Password success in fake-credential tests is not proof of a deployed authentication boundary.
  • Attachments, synchronization, native GUI and notarized packaging are not complete.
  • Broad macOS tests were completed before the latest documentation changes; Linux broad tests were before text-v2.

Keep credentials and private data outside the source checkout. Report problems without including passwords, tokens or private records.
