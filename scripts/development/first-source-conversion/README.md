# Development-only stopped first-source conversion

This test-only driver is excluded from installed products. No live store conversion has been run. It does not stop or restart services. An operator must arrange the authorized maintenance stop and a complete canonical backup first.

From the repository, run `python3 scripts/development/first-source-conversion/run.py --root /absolute/stopped/store --operation <canonical-UUIDv1> --actor-uid <current-administrator-UID> --confirm-service-stopped`. Preserve that exact operation, actor and explicit limits on retry. Defaults are finite: 8192 revision originals, 128 MiB aggregate original bytes, 262144 scanned entries, 10 GiB genuine available reserve plus four times admitted original bytes and 32 MiB temporary-work estimate. Explicit `--maximum-records`, `--maximum-bytes` and `--maximum-work` can raise admitted totals up to supported finite ceilings (32768, 16 GiB and 10000000); the driver never raises them automatically. Bootstrap pages contain at most 128 entries, independent of total policy. Fixture caps are separately much smaller.

The ordinary preflight resolves current administration before authority capture, independently enumerates canonical originals, verifies catalogue records, fixes path/digest/length/permission and operation allocations, then closes the writer. Authority-aware opening reacquires the lifetime writer, rechecks inputs and resolves current administration again before retention and pinning. Constructor capture alone grants no admission. Each original is reread and retained at its original canonical path. Exact retries reuse fixed IDs, journal frames and bootstrap bytes. Interruption or cancellation leaves a pending gate; do not delete it to make the service open. There is no automatic rollback or success receipt on error.

The private operation receipt stores metadata commitments, never copies of original contents. Accepted authority/journal/bootstrap files are the durable recovery evidence after completion. Keep pending receipts for exact continuation; complete receipts retain operation audit/retry information. Back up the complete canonical file recordstore including hidden identity/trust/lifecycle/initial-admission files, attachment binary originals, saved document content and private credential keys where applicable. Derived SQLite databases are rebuildable; binary payloads and secrets cannot be recreated from text. See `outputs/verification/cluster-2026-10-17/CLUSTER-REBUILD-CONTRACT.md` for the exact recovery boundary.

Public Setup/CLI creation and subsequent service/CLI authority-aware opens remain a separate unit. This source support does not activate clustering, enroll peers, modify the live installation, or publish a release.
